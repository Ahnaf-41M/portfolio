Selected work

Things I've built and run in production

01

Real-time notifications & a pending-tasks inbox

Gave users one screen for every item waiting on them, updating live. The view it replaced was roughly 10× slower on the same data.

  • Server pushes updates with Turbo Streams over Action Cable, broadcast from model changes — no polling, no manual refresh.
  • Stimulus controllers drive badge counts, read/seen state and Gmail-style toasts on the client.
  • Collapsed the "pending" lookup so the page renders in one pass instead of per-item work.
  • Rails
  • Hotwire
  • Turbo Streams
  • Action Cable
  • PostgreSQL
02

Metrics, dashboards & Slack alerting

Made the platform observable so failures surface to the team instead of to users.

  • Instrumented the app with Prometheus metrics — request rates, error rates, job health.
  • Built Grafana dashboards for day-to-day monitoring and incident triage.
  • Routed alerts into Slack so on-call-style notifications reach the team in real time.
  • Prometheus
  • Grafana
  • Slack
  • Rails
03

Server provisioning & container deploys

Turned environment setup and releases into repeatable, reviewed steps.

  • Wrote Ansible playbooks that take a bare server to a running app host — packages, users, runtime, service config.
  • Containerized the app and moved deploys to a container workflow driven by CI.
  • Maintained the CI/CD pipeline: automated tests gate every deploy.
  • Ansible
  • Docker
  • CI/CD
  • Linux
04

Migrating the view layer from HAML to ERB

Led a project-wide conversion so the codebase uses one templating language the whole Rails ecosystem already knows.

  • Converted every .html.haml template to .html.erb.
  • Worked through the whitespace-sensitivity and inline-Ruby edge cases HAML hides, checking rendered output page by page.
  • Result: lower onboarding cost for new contributors, one fewer DSL to learn.
  • Rails
  • ERB
  • Refactoring
